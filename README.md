# Блок комфорта электровелосипеда (ESP32)

Самодельный контроллер на ESP32 для электровелосипеда с китайским мотор-колесом и
бюджетным контроллером (KT-стиль). Цель — programmable throttle-by-wire, PAS,
свет/звук, настройка через WiFi, с прицелом на дальнейшее расширение (круиз,
дисплей, конструктор пинов).

## Два параллельных трека прошивки

Репозиторий содержит ДВЕ разные прошивки — это не ошибка, а сознательное решение:

- **`bike_comfort_firmware.ino`** — "большая" версия. Круиз-контроль, LED-матрица 8x32, меню на джойстике, поворотники/гудок через веб-эмуляцию. Была написана первой, как полная концепция проекта.
- **`bike_prototype_simple.ino`** — "тестовая"/текущая версия. Сильно урезана, чтобы получить рабочий велосипед быстро: throttle-by-wire с ПАС, приоритет тормоза, свет/звук передней группы, WiFi-настройки, живой отладочный график. **Это активная ветка разработки на сегодня.**


## 🚀 Начало работы и прошивка (Getting Started)

### Требования к оборудованию и ПО
- **Плата:** ESP32 DevKit (30 pin / 38 pin).
- **Среда разработки:** [Arduino IDE](https://www.arduino.cc/en/software) (2.x+) или VS Code с расширением Arduino / PlatformIO.
- **Пакет плат ESP32:** Версия ядра `3.x` от Espressif.

### Настройка Arduino IDE
1. В настройках IDE добавьте URL менеджера плат:
   ```text
   https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json
   ```
2. Установите пакет **esp32 by Espressif Systems** через `Tools` -> `Board` -> `Boards Manager...`.
3. Выберите плату: `ESP32 Dev Module`.
4. Параметры загрузки: Flash Frequency: `80MHz`, Upload Speed: `921600`.

## 📜 История ключевых решений (важно для контекста)

**Платформа.** Начинали с Arduino Nano, перешли на ESP32 (не хватало прерываний, ШИМ-каналов, нужен WiFi и встроенный ЦАП). Для раннего теста на столе использовали уже имеющуюся ESP32-CAM (свой программатор), финальная плата — обычный ESP32 DevKit.

**Газ (throttle-by-wire) — самая долгая итерация:**
1. Сначала думали тянуть сигнал параллельно (как тормоз) — отклонили: газ это активный сигнал (не сухой контакт), параллелить электрически некорректно.
2. Перешли на полный throttle-by-wire: режем провод, заводим в АЦП ESP32, выход — через встроенный ЦАП.
3. Обнаружили несостыковку напряжений: ESP32 работает на 3.3В, а ручка/контроллер — обычно до ~4.2В. Нужно согласование напряжений в обе стороны.
4. Промежуточный вариант — транзистор+RC-фильтр как "самодельный ЦАП" на выходе (без докупки деталей). Технически рабочий, но высокое выходное сопротивление — уязвимее к наводкам от мотора. Оставлен как запасной вариант, не основной.
5. **Финал (текущий):** операционный усилитель **MCP6002** (сдвоенный, rail-to-rail, питание 5В без всякого 12В) — канал А буферизует вход (делитель R1=10к/R2=20к), канал Б усиливает выход (R3=10к/R4=3.3к, коэффициент ~1.33). Низкоомный, помехоустойчивый сигнал в обе стороны.

**Тормоз и PAS — разная логика подключения:**
- Тормоз — пассивный сухой контакт, читается параллельно (тап), без риска для контроллера, без своего питания.
- PAS — у штатного контроллера этого узла вообще нет, датчик добавляется нами с нуля, поэтому питаем ourselves (от своих 5В), читаем через внутреннюю подтяжку ESP32 (работает, если датчик с открытым коллектором — как у большинства дешёвых Hall-дисков).

**Найденные грабли по ESP32:**
- "Минируемые" (strapping) пины GPIO0/2/5/12/15 — задействование GPIO12 под нагрузку однажды привело к буткрэш-лупу (выбор неверного напряжения флеша при старте). С тех пор эти пины не используются под силовые/тестовые выходы.
- ESP32-ядро 3.x поменяло API: `esp_task_wdt_init` требует структуру конфигурации (а не два аргумента), `ledcSetup`+`ledcAttachPin` заменены на единый `ledcAttach`.
- Классический баг автогенератора прототипов Arduino IDE: все `enum`/`typedef` вынесены в самое начало файла, до первой функции — иначе компилятор не видит типы в автоматически вставленных прототипах.

## ⚠️ Важные заметки по безопасности

- **Тормоз:** Всегда подключайте тормоз напрямую к мотор-контроллеру. Чтение тормоза этой платой — дублирующее, не основное средство безопасности.
- **Fail-safe:** При старте платы выход газа устанавливается в 0 до полной инициализации всех систем.
- **ESP32 — 3.3В логика.** Не подавайте напряжение выше 3.3В напрямую на GPIO/АЦП. Для сигналов с более высоким напряжением обязательно используйте согласование (делитель на входе, усилитель на выходе).
